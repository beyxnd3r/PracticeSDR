# Отчёт: Неделя 4 — Передача и приём I/Q-отсчётов с временными метками

## Цель работы

Продолжить изучение библиотеки **SoapySDR** и расширить программу предыдущей практики: настроить два потока **RX** и **TX** для ADALM-PLUTO, подготовить тестовые комплексные отсчёты и реализовать отправку буфера в заданный момент времени с использованием timestamp.

## Связь с предыдущей практикой

В [неделе 3](../week_3/) рассматривались настройка приёмного канала, чтение отсчётов и запись данных в PCM-файл. В четвёртой неделе к этим операциям добавлен **передающий канал**. Программа использует одно SDR-устройство и создаёт для него два потока — приёмный и передающий.

## Краткие теоретические сведения

Комплексный I/Q-отсчёт состоит из синфазной (**I**) и квадратурной (**Q**) компонент. При использовании формата `SOAPY_SDR_CS16` каждая компонента представлена 16-битным целым числом со знаком.

**Timestamp** — временная метка, которая позволяет связать принятый блок данных с определённым моментом времени. Если драйвер и устройство поддерживают запланированную передачу, метка вместе с флагом `SOAPY_SDR_HAS_TIME` задаёт время отправки TX-буфера.

## Настройка программы

Исходный файл практики — [`src/main.cpp`](src/main.cpp). Для работы используется SoapySDR с драйвером `plutosdr`.

| Параметр | Значение |
|---|---|
| Интерфейс подключения | `usb:` |
| Драйвер | `plutosdr` |
| Частота дискретизации RX/TX | 1 МГц |
| Центральная частота RX/TX | 800 МГц |
| Формат отсчётов | `CS16` |
| Усиление RX | 30 дБ |
| Усиление TX | −40 дБ |
| Дополнительные аргументы | `direct=1`, `timestamp_every=1920`, `loopback=0` |
| Число проходов цикла | 10 |
| Планируемая задержка TX | 4 мс |
| Выходной файл | `rxdata.pcm` |

Размеры RX- и TX-буферов программа получает через `SoapySDRDevice_getStreamMTU()`. Они не зафиксированы в исходном коде: значение `1920` задаётся отдельно в параметре `timestamp_every`.

## Ход работы

### 1. Подготовка каналов

После создания SDR-устройства программа устанавливает частоту и частоту дискретизации для RX и TX. Затем для канала `0` создаются потоки `SoapySDRDevice_setupStream()` и выделяются буферы с учётом их MTU.

### 2. Формирование передаваемых отсчётов

TX-буфер заполняется постоянными значениями **I = 2000** и **Q = 2000**. В его начале размещаются служебные слова `0xFFFF`. Часть буфера резервируется для восьми байтов рассчитанной временной метки; перед записью каждый байт сдвигается на четыре бита влево.

### 3. Приём и запланированная передача

После активации обоих потоков программа последовательно выполняет чтение RX-буферов. Для успешно прочитанного блока выводятся число отсчётов, время приёма и разница с предыдущей меткой.

Момент передачи определяется выражением:

```cpp
long long scheduled_time = rx_time + 4000000LL;
```

При интерпретации метки в наносекундах добавка соответствует **4 мс**. На третьем проходе цикла (`cycle == 2`) программа вызывает `SoapySDRDevice_writeStream()` с флагом `SOAPY_SDR_HAS_TIME` и рассчитанной меткой. При этом результат отправки проверяется по коду возврата функции.

Принятые отсчёты сохраняются в бинарный файл `rxdata.pcm`. Записывается только то количество сэмплов, которое реально вернул `readStream()`.

## Сборка и запуск

Проект собирается через CMake с подключением SoapySDR:

```bash
cd week_4
cmake -S . -B build
cmake --build build
cd build
./main
```

При запуске из каталога `build` программа создаёт `build/rxdata.pcm` (при условии успешного подключения SDR и получения данных).

## Результат и вывод

В рамках четвёртой недели подготовлен алгоритм полнодуплексной работы: создана настройка RX/TX, реализованы чтение и сохранение I/Q-отсчётов, заполнение передающего буфера и запрос отправки в определённый момент времени.

По сравнению с неделей 3 программа стала работать не только с приёмником, но и с передатчиком, что создаёт основу для дальнейших экспериментов по синхронизированному обмену сигналами.

**Ограничение:** наличие кода и графика не подтверждает успешное аппаратное выполнение эксперимента. Для проверки передачи, приёма и временных меток необходимо совместимое подключённое устройство ADALM-PLUTO и его журналы работы. Без физического SDR в WSL можно проверить сборку и обработку заранее записанных либо смоделированных данных, но не радиопередачу.
